# ТЗ: TGAds — софт для запуска Telegram-каналов и закупа рекламы (рынок Узбекистана)

## 0. Цель

Один инструмент, который проводит через весь цикл:

```
Ниша и идея → Канал и контент → Отбор площадок (без накрутки) → Контакты админов
→ Переписка и цена → Покупка → Отслеживание отдачи по каждой площадке
```

Основная метрика: **цена живого подписчика (CPS)** по каждой площадке и каждому креативу.

## 1. Принятые решения

| Вопрос | Решение |
|---|---|
| Интерфейс | Только веб-панель (браузер), без бота-уведомлятора |
| ИИ | Claude **без API-ключа**: локальный Claude Code CLI (`claude -p`), залогиненный в подписку. Фолбэк: ручной режим (панель показывает промпт, ответ вставляешь из чата). Если когда-нибудь появится ключ — режим `api`. |
| Язык | Задаётся у каждого своего канала: `uz` (латиница), `uz_cyrl`, `ru` |
| Переписка с админами | Полуавтомат: софт пишет по шаблону с твоего ТГ-аккаунта, ИИ вытаскивает цену/формат из ответа и считает CPM, решение о покупке и оплату делаешь ты |
| Источник данных | Свой парсинг через Telegram-аккаунт (Telethon, MTProto) — бесплатно. TGStat API — опционально, если купишь токен (поиск каналов по стране/категории, упоминания, история подписчиков) |
| Стек | Python 3.11+, FastAPI + Jinja2 + htmx + Chart.js, SQLite (SQLAlchemy async), Telethon |
| Запуск | 24/7 на VPS (Docker) или на своём ПК. Для модуля 3 процесс должен работать постоянно |
| Часовой пояс | Asia/Tashkent (UTC+5) |
| Валюта | Сум (UZS) основная; USD и RUB конвертируются по курсу из настроек |

## 2. Что нужно от тебя для запуска

1. `api_id` и `api_hash` с https://my.telegram.org (один раз).
2. Telegram-аккаунты (лучше отдельные, не основной):
   - **monitor** — вступает в каналы-кандидаты и следит за просмотрами. Лимит Telegram: ~500 каналов на аккаунт (1000 с Premium).
   - **outreach** — пишет админам. Новые/«холодные» аккаунты быстро ловят спамблок, лучше аккаунт с историей.
   - **publisher** — админ твоих каналов: публикует посты, создаёт пригласительные ссылки.
   Один аккаунт может совмещать все роли.
3. Claude Code на машине, где крутится софт: `npm i -g @anthropic-ai/claude-code`, потом `claude` → войти в подписку. Если не ставить, будет работать ручной режим ИИ.

## 3. Модули

### Модуль 1. Ниши и идеи («что запускать и с каким рекламным постом»)

**Задача:** найти темы, которые уже работают в UZ-сегменте, и рекламные посты, которые реально окупаются.

**Сбор каналов (источники):**
- Поиск по ключевым словам через Telegram (`contacts.Search`) — набор UZ/RU ключей по тематикам.
- Импорт списка `@username` / `t.me/...` вручную (например, скопировал из каталога TGStat `uz.tgstat.com`).
- **Снежный ком:** из собранных постов вытаскиваются все упомянутые каналы (`@user`, `t.me/...`) → новые кандидаты. В UZ-сегменте каналы активно рекламируют друг друга, так что этот источник даёт больше всего.
- TGStat API `channels/search` (country=uz, category) — если есть токен.

**По каждому каналу считаем:** подписчики, средние просмотры поста за 24–72 ч, ERR (охват / подписчики), частоту постинга, пересылки и реакции на 1000 просмотров, долю рекламных постов, дату последнего поста, примерный возраст канала.

**Тематика:** ИИ классифицирует каналы пачками по названию, описанию и 3 последним постам в фиксированный список тематик (новости, юмор, футбол, авто, работа/вакансии, IELTS/образование, Uzum/скидки, кино, рецепты, бизнес, крипта, ислам, здоровье/красота, мамы, путешествия, психология/мотивация, техника, недвижимость, музыка, прочее).

**Таблица ниш** — по каждой тематике:
- число каналов, суммарный и медианный охват;
- медианный ERR (живость аудитории);
- **входящая реклама**: сколько рекламных постов с упоминанием каналов этой ниши найдено. Чем больше, тем активнее в нишу льют деньги, то есть она окупается;
- рекламоёмкость: доля рекламы в постах каналов ниши (на чём будет монетизация);
- Opportunity score = спрос (охваты, входящая реклама) / конкуренция (число каналов, концентрация охвата в топ-3).

**Рекламные креативы (главное):**
- Детектор рекламных постов: метки `#реклама`, `#reklama`, `erid`, «Реклама», `Homiy`, ссылки-приглашения `t.me/+...`, CTA «Подписывайся» / «Obuna bo'ling», короткий пост с одной внешней ссылкой на канал.
- Кластеризация одинаковых креативов (шинглы + Jaccard ≥ 0.6): один текст, размещённый в разных каналах, — это один креатив.
- **Ранжирование:** креатив, который рекламодатель **покупает повторно** в разных каналах и в течение долгого времени, окупается — иначе бы перестали. Score = число размещений × разные площадки × длительность использования (дни).
- По каждому креативу: рекламируемый канал, площадки, даты, просмотры размещений.
- Кнопка «Сделать похожий для моего канала» → ИИ пишет 3–5 вариантов на нужном языке по структуре лучшего креатива.

**ИИ-генерация идей:** на вход таблица ниш + топ креативов → 5–10 идей каналов: название, позиционирование, контент-план, 2 варианта рекламного поста, риски.

### Модуль 2. Контент

- У каждого твоего канала есть **доноры** — похожие каналы.
- Парсинг постов доноров: текст, медиа, просмотры, пересылки, реакции, комментарии.
- **Оценка поста** (нормированная, чтобы сравнивать каналы разного размера):
  `score = 0.4·(views / медиана просмотров донора) + 0.35·(forwards на 1000 просмотров / медиана) + 0.25·(reactions на 1000 / медиана)`; сравниваются только посты старше 24 ч.
  Рекламные посты доноров исключаются.
- **Лучшие посты** → действия:
  - «Рерайт» — ИИ переписывает на язык канала, убирает подписи, ссылки и упоминания донора;
  - «Как есть» — копия с медиа (медиа скачивается и перезаливается, работает и для каналов с запретом пересылки);
  - «Сгенерировать с нуля» — ИИ пишет пост по теме канала.
- **Очередь публикаций:** черновики → редактирование → публикация по расписанию (слоты по времени Ташкента) с аккаунта publisher.
- Дедупликация: один и тот же пост дважды не берём (хеш текста и медиа).

### Модуль 3. Отбор площадок и проверка на накрутку

**Кандидаты** — из модуля 1 (любые собранные каналы), фильтр по тематике, охвату и ERR.

**Статическая проверка** (сразу, по последним 50 постам):
- ERR > 80% без пересылок — подозрительно (накрутка просмотров);
- ERR < 3% — мёртвые или накрученные подписчики;
- коэффициент вариации просмотров постов старше 48 ч < 0.08 — «ровные» просмотры, характерно для ботов;
- пересылки ≈ 0 и реакции ≈ 0 при большом охвате.

**Динамическая проверка (основная, по твоей идее):**
1. Аккаунт monitor вступает в канал (с паузами и дневным лимитом, канал уходит в архив без звука).
2. Новый пост ловится двумя путями: событие `NewMessage` и опрос `messages.getPeerDialogs` пачками по 100 каналов каждые ~20 с (страховка от пропуска апдейтов).
3. Замеры просмотров на отметках **30 с, 1, 2, 3, 5, 10, 15, 30, 45 мин, 1, 2, 3, 4, 6, 8, 12, 16, 24, 48 ч** от времени публикации поста (`message.date`). Одним запросом `messages.getMessagesViews` снимаются просмотры и пересылки всех постов канала сразу. Хранятся сырые точки (секунды от публикации, просмотры, пересылки), поэтому опоздание на 10–20 с ничего не ломает.
4. **Эталонная кривая:** доля от 24-часовых просмотров S(t) = V(t)/V(24h). Стартует с априорной кривой, затем пересчитывается медианами по всем отслеженным постам (медиана устойчива к накрученным выбросам). Отдельные кривые для дневных (8–23 по Ташкенту) и ночных постов.
5. **Прогноз на сутки:** V̂(24h) = V(t) / S(t) по самому позднему замеру до 30-й минуты. Интервал [p25; p75] — по квантилям долей.
6. **Флаги поста:**
   - `late_boost` — фактические V(24h) больше прогноза по ранним минутам в ≥ 2.2 раза (порог настраивается). Это главный признак: «в первые минуты почти ничего, а через сутки дохера»;
   - `dead_start` — за 5 мин < 0.3% подписчиков, а за сутки > 15%;
   - `instant_dump` — за первые 2 мин > 45% суточных просмотров (боты в начале);
   - `rate_spike` — скорость прироста просмотров в позднем интервале выросла в ≥ 3 раза относительно предыдущего, а пересылки при этом не выросли (порционная накрутка).
7. **Вердикт канала** (после ≥ 3 отслеженных постов): `clean` / `suspicious` / `boosted` + score 0–100 + список причин.
8. **Честный охват** = медиана прогнозов по ранним минутам (бот-накрутку обычно не дают в первые минуты). Это и есть ожидаемые просмотры твоего рекламного поста, и от него считается CPM.

На странице канала — график: кривые просмотров его постов поверх эталона.

### Модуль 4. Контакты

- Для отобранных каналов: полное описание (`channels.getFullChannel`) + закреплённый пост (часто там прайс).
- Извлечение: `@username`, `t.me/username`, телефоны (+998…), e-mail, ссылки на прайс-каналы и ботов. Приоритет — контакты рядом со словами «реклама / reklama / ads / по рекламе / reklama bo'yicha / murojaat / admin / менеджер».
- Резолв username: пользователь, бот или канал (прайс-канал → один шаг вглубь, ищем контакты в его описании).
- **Дедупликация менеджеров:** один менеджер продаёт рекламу в сетке каналов, поэтому группируем — можно просить пакетную цену.

### Модуль 5. Переписка и закуп (полуавтомат)

- Шаблоны первого сообщения на uz/ru с переменными (`{channel}`, `{format}`, `{topic}`). ИИ может слегка варьировать текст, чтобы не было одинаковых сообщений (антиспам).
- Отправка с аккаунта outreach: дневной лимит новых диалогов (по умолчанию 15), случайные паузы 60–240 с, только в рабочие часы.
- Входящие ответы ловятся автоматически → диалог в панели.
- **Разбор ответа:** ИИ (и регулярки как фолбэк) извлекают цену, валюту, формат (`1/24`, `2/48`, `1/72`, `навсегда / abadiy`), скидки, свободные даты и прайс по сетке каналов.
- Расчёт: CPM = цена / честный охват × 1000, сравнение с целевым CPM → рекомендация «брать / торговаться / пропустить».
- Ответить можно из панели: вручную или черновиком от ИИ.
- «Покупаем» → запись **Закупка** (площадка, дата/время выхода, формат, цена, креатив, статус оплаты) + автоматически трекинг-ссылка (модуль 6).

### Модуль 6. Отслеживание отдачи

- На каждую закупку создаётся **отдельная пригласительная ссылка** твоего канала (`messages.exportChatInvite` с названием `ad:<площадка>:<дата>`). Можно включить режим заявок (`request_needed`): данные точнее, но конверсия немного ниже.
- Сбор: вступления по ссылке (с временем), отписки вступивших (через admin log канала) на 1, 3 и 7 день.
- Поиск самого рекламного поста в канале-площадке (по нашей ссылке) и замер его просмотров тем же монитором (проверяем, не крутили ли во время нашего поста).
- **Отчёт по закупке:** цена, просмотры поста, подписались, CTR = вступления / просмотры, CPM, **CPS = цена / вступления**, удержание через 7 дней, цена живого подписчика.
- Сводка по площадкам и креативам: где и какой пост окупается лучше всего.

## 4. Архитектура

```
tgads/
  tgads/
    config.py          настройки (.env)
    db.py, models.py   SQLite, модели
    ai/                провайдеры ИИ (claude_cli | api | manual), очередь ИИ-задач, промпты
    analysis/          чистая логика без сети (тестируется): кривые, прогнозы, накрутка,
                       скоринг постов, детектор рекламы, контакты, цены, кластеризация, ниши
    tg/                Telethon: аккаунты, сборщик, монитор, публикация, переписка, ссылки
    services/          сценарии модулей поверх tg/ + analysis/ + db
    web/               FastAPI, страницы, шаблоны
    worker.py          фоновые циклы (монитор, публикации, ИИ-очередь, трекинг)
  tests/
  docs/TZ.md
```

Один процесс: веб-панель + фоновые задачи (asyncio). Telethon-клиенты живут в пуле внутри процесса.

**ИИ-задачи** — единая очередь `ai_jobs` (тип, промпт, статус, результат). Режим `claude_cli` или `api` — воркер выполняет сам. Режим `manual` — задача ждёт на странице «ИИ-задачи», пока ты вставишь ответ. После ответа срабатывает обработчик по типу задачи (сохранить рерайт, разобрать цену и т.д.).

## 5. Модель данных (основное)

- `accounts` — ТГ-аккаунты (телефон, session, роли, статус, лимиты)
- `my_channels` — свои каналы (язык, тематика, доноры, расписание)
- `channels` — все внешние каналы (статы, тематика, источник, статус проверки, вердикт)
- `channel_snapshots` — история подписчиков и охватов
- `posts` — посты внешних каналов (текст, медиа-флаги, просмотры, пересылки, реакции, is_ad, упоминания)
- `view_samples` — точки кривой просмотров (post, t_sec, views, forwards)
- `creatives` — кластеры рекламных постов
- `contacts` + `channel_contacts` — контакты и их связь с каналами
- `conversations`, `messages` — переписка
- `offers` — извлечённые предложения (цена, формат, CPM)
- `purchases` — закупки
- `invite_links`, `joins` — трекинг
- `content_items` — черновики и очередь публикаций
- `ai_jobs` — ИИ-задачи
- `settings` — ключ-значение (курсы валют, пороги, целевой CPM)

## 6. Ограничения и риски

- **Флуд-лимиты Telegram.** Все запросы идут через обёртку с обработкой `FloodWaitError`. Вступление в каналы — не больше ~30–40 в сутки на аккаунт.
- **Спамблок outreach-аккаунта** при массовой рассылке незнакомым. Поэтому лимиты, паузы и вариативность текста; проверка статуса через @SpamBot — в следующей итерации.
- **Апдейты каналов** могут приходить с задержкой, поэтому параллельно работает опрос `getPeerDialogs`.
- **TGStat:** сайт не парсим (Cloudflare и правила сервиса), только официальный API по токену.
- **Прогноз на сутки** зависит от канала и времени суток. Поэтому кривые раздельные (день/ночь), выдаётся интервал, а пороги настраиваются.
- **Копирование чужого контента «как есть»** — риск жалоб от правообладателей. По умолчанию — рерайт.

## 7. Этапы

1. **MVP (текущая итерация):** все 6 модулей в базовом виде, панель, ИИ-очередь, монитор просмотров, трекинг-ссылки, тесты аналитики.
2. Калибровка порогов накрутки на реальных данных (нужно 2–3 недели мониторинга сотни каналов).
3. TGStat API (если купишь): поиск по стране, история подписчиков, упоминания.
4. Проверка спамблока, ротация аккаунтов, автоматическое предложение пакетов по сеткам менеджеров.
5. Автопостинг с A/B-тестом креативов (разные ссылки на разные креативы в одной площадке).
