# TGAds — памятка для Claude

Отвечай владельцу по-русски, коротко и по делу. Владелец хочет, чтобы ты работал самостоятельно: делай сам, а не присылай ему команды. Пользуется в основном телефоном.

Сведения о конкретном сервере (адреса, общие с другими проектами службы, текущие проблемы) в этот публичный репозиторий не кладём. Они лежат рядом с рабочей копией на сервере, в `CLAUDE.local.md` (файл в `.gitignore`).

## Что это

Веб-панель для запуска Telegram-каналов на рынке Узбекистана и закупа рекламы. Шесть модулей:
1) ниши и рекламные креативы, 2) контент, 3) проверка площадок на накрутку по динамике просмотров,
4) контакты админов, 5) переписка с админами (полуавтомат), 6) отдача по трекинг-ссылкам.
ТЗ: `docs/TZ.md`, запуск и деплой: `README.md`.

Решения владельца (не менять без него):
- Интерфейс только веб-панель, без бота. Должна открываться с телефона, есть PWA.
- ИИ — Claude **без API-ключа**: локальный `claude -p` по подписке. Для фонового сервиса используется токен `claude setup-token`
  (переменная `TGADS_CLAUDE_OAUTH_TOKEN` в `.env` или поле в «Настройках» панели). Запасной вариант — ручной режим.
- Язык каждого своего канала задаётся отдельно: `uz`, `uz_cyrl` или `ru`.
- Переписка — полуавтомат: пишем по шаблону, ИИ разбирает цену, покупку подтверждает владелец.
- TGStat — только скрапер (платный API владелец брать не будет). Есть пауза между запросами, кэш,
  Chromium на случай Cloudflare и вставка HTML вручную.
- Проверка накрутки (главная идея владельца): замер просмотров с 30 с до 48 ч, прогноз суток по первым 30 минутам, сравнение с фактом.

## Код

- `tgads/analysis/` — чистая логика без сети, покрыта тестами: кривые и детектор накрутки (`views.py`), реклама и score постов (`posts.py`),
  контакты, цены и CPM (`pricing.py`), ниши и креативы, парсер TGStat.
- `tgads/services/` — сценарии модулей на Telethon: research, monitor, contacts, outreach, content, tracking, tgstat.
- `tgads/tg/pool.py` — Telegram-аккаунты (вход по коду в панели, файловые сессии в `data/sessions`).
- `tgads/ai/` — провайдеры (`claude_cli` / `api` / `manual`) и очередь ИИ-задач.
- `tgads/web/` — FastAPI + Jinja; Pico CSS и Chart.js лежат в `static/vendor`.
- `tgads/worker.py` — фоновые циклы (сбор, монитор, отправка сообщений, публикации, трекинг).
- Важно: не держать запись в SQLite открытой во время сетевых запросов. Сначала сеть, потом короткая сессия на запись.
- Ленивые связи SQLAlchemy в async не использовать, всё загружать явными запросами.

Проверки: `pip install -r requirements-dev.txt && pytest` — 30 тестов, включая полный сценарий на фейковом Telethon-клиенте.

## Правила

- Репозиторий **публичный**: никаких секретов, адресов серверов и паролей в коммитах, логах и PR.
- Рабочая ветка `claude/telegram-channel-ads-platform-8qn7b8`, черновой PR №1.
- Установка на Windows: `deploy/windows/install.ps1` (по умолчанию всё в `C:\Apps\TGAds`).
  Папка `src` при каждой установке перезаписывается, поэтому разработку ведём в отдельном клоне репозитория.
  Выкатываем так: пуш в ветку, затем `install.ps1 -Unattended`.
- На общем сервере не трогать чужие приложения и их общий Caddy без необходимости. Перед правкой Caddyfile делать резервную копию и `caddy validate`.
- С настоящим Telegram, живым TGStat и на Windows код ещё ни разу не проверялся. Ошибки на первом запуске ожидаемы, исправляй по логам (`logs\tgads.log`, `logs\crash.log`).
